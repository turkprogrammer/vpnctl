# Вклад в vpnctl

Спасибо за интерес к проекту! Инструмент небольшой и строится на принципах
**KISS, YAGNI, DRY** — перед любым изменением подумайте, можно ли сделать проще.

## Требования

- Linux x86_64 (Ubuntu).
- Go 1.26+.
- Для сборки GUI — `libgtk-3-dev`, `libayatana-appindicator3-dev`
  (`sudo apt install libgtk-3-dev libayatana-appindicator3-dev`).
- Для запуска привилегированных команд — `awg`, `awg-quick`, `pkexec`.

## Быстрый старт

```bash
# Склонировать и собрать
git clone <ваш форк>.git vpnctl
cd vpnctl
go build -mod=vendor -o vpnctl .

# Проверить состояние (работает без прав root)
./vpnctl status

# Тесты
go test ./...
```

Сборка использует каталог `vendor/` (зависимость `gotk3` зафиксирована и
пропатчена при необходимости — см. раздел «Известные проблемы» в README).

`status` и мониторинг статуса выполняются от обычного пользователя и не требуют
пароля. Привилегированные операции (`up`, `down`, `import`) в тестах можно
изолировать от системы:

```bash
VPNCTL_CONF_DIR=/tmp/vpnctl-test ./vpnctl import example.conf
VPNCTL_IP_URL=http://127.0.0.1:8080 ./vpnctl status
```

## Процесс работы

1. Форкните репозиторий.
2. Создайте ветку: `git checkout -b feat/my-feature`.
3. Внесите изменения.
4. Убедитесь, что всё собирается: `go build -mod=vendor ./...`.
5. Запустите `go vet ./...` и `go test ./...`.
6. Закоммитьте с сообщением в стиле репозитория (префикс `vpnctl:`),
   например: `vpnctl: add foreign-key to app`.
7. Откройте Pull Request, кратко описав, что меняется и почему.

## Правила кода

- Экспортированные символы (функции, типы, переменные, пакеты) должны иметь
  godoc-комментарии: что делает, когда использовать, какие ошибки возможны.
  Внутренняя логика тоже документируется там, где «почему» не очевидно.
- **Привилегии повышаются только через `internal/priv`** (`Run` / `RunWG` /
  `TryWG`) — никаких личных `sudo`/`pkexec` вызовов в других пакетах.
- Приватный ключ живёт только в системном конфиге (`0600`, владелец `root`),
  в приложении секреты не дублируются.
- Новая логика по умолчанию не добавляется (YAGNI): фича попадает в код только
  после явной постановки задачи.
- Изменения темы GUI — только в `internal/ui/style.go` (CSS, одиночная
  таблица стилей, окно не зависит от темы рабочего стола).
- Состояние из фоновых горутин в главный цикл GTK передавать через
  `glib.IdleAdd`; защищать реентрабельные сигналы (например `syncing`/`busy`
  в обработчике тоновой кнопки).
